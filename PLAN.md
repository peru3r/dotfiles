# План автоматизации развертывания dotfiles

## 1. Цель

Развертывать конфигурации и необходимые зависимости на macOS, Linux и WSL одной командой. Установка должна учитывать особенности ОС, поддерживать повторный запуск, предварительный просмотр действий и восстановление существующих конфигов.

Основные компоненты: Zsh, Oh My Zsh, Neovim, tmux, Alacritty; для macOS дополнительно yabai и skhd.

Этот документ описывает будущую реализацию. Приведенные команды и пути новых файлов — проектируемый интерфейс, а не уже доступные возможности репозитория.

## 2. Предлагаемый подход

Использовать **Bash для определения окружения и установки зависимостей + Dotbot для развертывания символических ссылок**.

Причины:

- Существующую структуру конфигов можно сохранить.
- Пакеты устанавливаются нативным пакетным менеджером ОС.
- Dotbot берет на себя создание ссылок, родительских каталогов и обработку части конфликтов.
- Общий установщик управляет профилями, порядком действий, диагностикой и журналом установки.
- Конфиги остаются обычными файлами в Git: изменения через символические ссылки сразу видны в репозитории.

Dotbot фиксируется на **v1.24.1 через Git submodule**. Обновление выполняется вручную, отдельно от обычного запуска install. Bash используется для bootstrap, установки пакетов и системной настройки; Dotbot — для управления dotfiles и символическими ссылками. Перед интеграцией проверить возможности именно v1.24.1, включая backup и dry-run; если они не покрывают требования плана, вынести решение на согласование. Предусмотреть совместимый Python до запуска Dotbot.

Для сравнения архитектуры изучить chezmoi: он полезен при большом количестве различающихся машин и шаблонов. В текущем плане платформенные различия реализуются небольшими модулями конфигурации и установщика.

## 3. Исходное состояние и необходимые исправления

### Zsh и Oh My Zsh

- `.zshrc` содержит персональный путь `/Users/peru3re/.lmstudio/bin`.
- Пути `/opt/homebrew/bin` и вызов `brew --prefix coreutils` привязаны к macOS; вызов `brew` выполняется без проверки его наличия.
- Используется тема `alanpeabody`; собственная `zsh/oh-my-zsh/guts.zsh-theme` присутствует, но не активирована.
- `zsh/env.zsh` пустой.
- Alias `cat=bat` требует учета имени `batcat` в Debian/Ubuntu.
- NVM подключается в интерактивной конфигурации, но установщик должен подключать его самостоятельно.

### tmux

- Копирование в `tmux/tmux.conf` использует `pbcopy`, доступный в macOS.
- Нужен выбор backend для Linux Wayland, Linux X11 и WSL.
- Для `default-terminal = tmux-256color` нужно проверять наличие соответствующего terminfo.

### Alacritty

- Импортируется `~/.config/alacritty/themes/guts.toml`, но README предлагает копирование в `themes/themes/`.
- Шрифт `Hack Nerd Font` или `Comic Mono`должен быть установлен в системе, где работает терминал.
- Путь `/bin/zsh`, локаль `en_US.UTF-8` и оформление `Buttonless`(только для MacOS) требуют проверки или платформенных настроек. Для MacOS - `Buttonless`, для остальных ОС - `Full`.
- Для собственной темы `guts.toml` не требуется клонировать всю коллекцию сторонних тем.

### Neovim

- Использование `vim.lsp.config` и `vim.lsp.enable` требует Neovim 0.11 или новее. Выбранные версии плагинов могут предъявлять дополнительные требования. (по идее я буду всегда ставить последнюю версию Neovim)
- В Git отсутствует `lazy-lock.json`. - добавил
- Нужно проверить совместимость конфигурации Treesitter с выбранной версией плагина.
- Для Python LSP нужен Pyright, для форматирования через none-ls — Prettier.
- Telescope использует `ripgrep`; сборка `telescope-fzf-native.nvim` требует `make` и C-компилятора.
- В биндах запуска используются `python3` и `gcc`.
- README ссылается на clipboard-блок для WSL в `nvim/init.lua`, но такого блока нет. - убрал, просто сделать поддержку копирования на разных платформах.

### yabai и skhd

- Компоненты предназначены только для macOS.
- В `yabai/yabairc` ошибочный shebang: `#!usr/bin/env sh`.
- Загрузка scripting addition через `sudo yabai --load-sa` выполняется безусловно.
- Необходимо отделить базовую установку от настройки scripting addition под конкретную версию macOS.
- Переключение Spaces и другие используемые возможности нужно проверить в выбранном режиме работы yabai.
- Я в целом не до конца разобрался с конфигом yabai и skhd поэтому может быть много ошибок. Более детально разберусь в другом потоке.


### Документация

- README содержит отдельные команды, но не полный сценарий развертывания.
- Команды `cp skhd ...` и `cp yabai ...` не копируют каталоги без соответствующего флага.
- Node 23 следует заменить согласованной поддерживаемой LTS-версией.

Согласованный охват:

| Окружение | Установка зависимостей | Особенности |

| macOS Apple Silicon | Homebrew, Command Line Tools | Текущая версия 15.7.3; macOS 27 — будущая цель, требующая проверки после появления |

Версии Linux-дистрибутивов пока не указаны. Поддержка Intel Mac не требуется. Для неизвестного дистрибутива выдавать понятное сообщение; режим развертывания только конфигов может работать при уже установленных зависимостях.

Текущий объем: развертывание конфигов и основных зависимостей. Автоматическую установку приложений и scripting addition yabai перенести в TODO.

| --- | --- |
| `cli` | Zsh, Oh My Zsh, Neovim, tmux, bat, tree, зависимости редактора |

WSL по умолчанию использует `cli`. Терминал — **Alacritty для Windows**, запускающий WSL:

```toml
[terminal.shell]
program = "wsl.exe"
args = ["~"]
```

Конфиг терминала и шрифт находятся на Windows-хосте. Способ доставки конфига Alacritty из WSL в Windows согласовать при работе над соответствующим пунктом этапа 1.

## 5. Предлагаемая структура

```text
install.sh
install.conf.yaml              # общие ссылки Dotbot
install.desktop.conf.yaml      # конфиги desktop
install.macos-wm.conf.yaml     # ссылки yabai/skhd
vendor/dotbot/                 # зафиксированный Git submodule
scripts/
  lib/
    detect.sh                  # ОС, дистрибутив, архитектура, WSL
    packages.sh                # адаптеры пакетных менеджеров
    state.sh                   # журнал, backup, восстановление
  doctor.sh                    # диагностика
  restore.sh                   # восстановление по журналу
manifests/
  packages/
    Brewfile
    apt.txt
    dnf.txt
    pacman.txt
  versions.env                 # выбранные версии инструментов
zsh/
  env.zsh
  os/
    macos.zsh
    linux.zsh
    wsl.zsh
```

Существующие каталоги `nvim/`, `tmux/`, `alacritty/`, `skhd/`, `yabai/` и `zsh/oh-my-zsh/` сохранить. Окончательное размещение платформенных настроек Alacritty определить после проверки поддерживаемой версии приложения.

## 6. Интерфейс установщика

```bash
# Предварительный просмотр всех этапов
./install.sh --profile cli --dry-run

# Базовое окружение
./install.sh --profile cli

# Графическое окружение macOS с yabai/skhd
./install.sh --profile desktop --with macos-wm

# Только конфиги, зависимости уже установлены
./install.sh --links-only

# Проверка установленного окружения
./scripts/doctor.sh
```

Дополнительно предусмотреть `--help`, явный параметр смены login shell и восстановление по идентификатору установки.

Требования к реализации:

- Совместимость со стандартным Bash macOS либо явно описанный bootstrap более новой версии. Предпочтительно использовать совместимый синтаксис.
- Корень репозитория определяется относительно скрипта, а не текущего рабочего каталога.
- Поддерживаются пути с пробелами и `$XDG_CONFIG_HOME`.
- WSL определяется до выбора обычных Linux-интеграций.
- `--dry-run` распространяется на весь установщик: никаких загрузок, установки пакетов, создания каталогов и изменения файлов.
- Отсутствие Python или Dotbot в dry-run показывается как будущий шаг, без их установки.
- Повторный запуск завершает недостающие этапы и не обновляет автоматически зафиксированные версии.

## 8. Критерии готовности

1. На каждой согласованной платформе есть проверенный сценарий установки выбранного профиля.
2. Повторный запуск не создает дубликаты, лишние backup и повторные записи в shell-конфигах.
3. Конфликтующие конфиги сохраняются, а восстановление проверено.
4. Dry-run показывает все планируемые действия без изменений и загрузок.
5. Neovim запускается, Python LSP подключается, Prettier и Telescope работают.
6. Копирование из tmux и Neovim работает в поддерживаемых графических сессиях и WSL.
7. Версии плагинов воспроизводятся из lockfile; обновление выполняется отдельно.
8. Doctor выдает понятный результат и перечисляет незавершенные действия.
9. В README есть актуальная команда установки и точная матрица поддержки.

### holman/dotfiles — модульные shell-скрипты

Репозиторий: https://github.com/holman/dotfiles

Что изучить:

- [zsh/](https://github.com/holman/dotfiles/tree/master/zsh) — модульная конфигурация shell.

Полезная идея: каталоги по инструментам, `*.symlink` для развертывания и `install.sh` для установки компонента. Проект ориентирован преимущественно на macOS.

Репозиторий: https://github.com/driesvints/dotfiles

Полезные идеи: Homebrew Bundle и документация первоначальной настройки. Скрипт персональный и, например, удаляет существующий `.zshrc` перед созданием ссылки; в нашей реализации нужна обработка конфликтов и повторного запуска.

### anishathalye/dotbot — готовый механизм развертывания ссылок

Репозиторий: https://github.com/anishathalye/dotbot

Что изучить:

- [Full example](https://github.com/anishathalye/dotbot#full-example).
- [Link](https://github.com/anishathalye/dotbot#link).
- [Шаблон dotfiles-репозитория](https://github.com/anishathalye/dotfiles_template).

В просмотренной документации описаны backup, условные ссылки, dry-run и выборочный запуск директив. Доступность этих возможностей проверить для выбранной фиксированной версии.

Иллюстрация будущего конфига для текущего репозитория; XDG-пути и профили потребуется учесть при реализации:

```yaml
- defaults:
    link:
      create: true
      relink: true
      backup: true

- link:
    ~/.zshrc: .zshrc
    ~/.config/nvim: nvim
    ~/.tmux.conf: tmux/tmux.conf
    ~/.config/alacritty/alacritty.toml: alacritty/alacritty.toml
    ~/.config/alacritty/themes/guts.toml: alacritty/guts.toml
```

Рекомендуемый порядок изучения: **holman → felipecrs → Dotbot → twpayne → driesvints**.
